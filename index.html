Gêmeo Digital de Niterói

Abrir o Gêmeo

Toda cidade já tem dados. O que falta quase nunca é dado: é o encontro entre eles.

Mini Gêmeo o mesmo cruzamento, rodando aqui no navegador
Estado no último ciclo ·
Carregando a malha viária…
Camadas

Somem só ônibus, alertas e lentidão, que saem do cruzamento. Malha e chuva continuam: a falha fica localizada num lado só.

normalalertjammedalert_jammed

Clique num ônibus para ver os detalhes. Ônibus e ocorrências são simulados sobre as ruas reais; tempo acelerado 8×, ciclo de 3 s no lugar de 30 s. Não há uma API pública da MobNit acessível daqui.

Para que serve

Num mapa comum, o alerta do Waze e a posição do ônibus ficam separados. O Gêmeo cruza as fontes a cada 30 segundos e responde o que está sendo afetado, por quê e o que fazer. É público em gemeo.niteroi.rj.gov.br e usado pelas equipes da Prefeitura.

O que a tela mostra

Oito camadas, de oito órgãos: ônibus, alertas e lentidão do Waze e chuva da Defesa Civil passam pelo cruzamento; NitBike, câmeras, rotas e edificações 3D só aparecem. Cada ônibus ganha uma cor por estado.

Como eu fiz

  • Interface em React e TypeScript com ArcGIS Maps SDK: cena 3D, camadas, pop-ups, símbolos e filtros por período.
  • Estado da interface em stores com Zustand, alimentado pelo SSE.
  • Apresentação do projeto para outras equipes.

Cache e envio

Um evento para todos os navegadores

BFFRedis 60 sSSENginxnavegadornavegador

O estado vai para o Redis com TTL de 60 s, e um lock garante que só uma instância rode o ciclo. Server-Sent Events levam o resultado pelo Nginx, sem buffer: quem abre agora lê o cache, quem já está aberto recebe o evento. A stack sobe inteira com Docker Compose.

Por dentroCiclo de 30 s, regra de estado e infraestruturaabrir a parte técnica

O ciclo de 30 segundos

A regra que decide a cor

normal 
// packages/shared/src/domain/Bus.ts
getStatus(): "normal" | "alert" | "jammed" | "alert_jammed" {
  if (isAlert && isJammed) return "alert_jammed";
  if (isAlert || isFlooded) return "alert";
  if (isJammed) return "jammed";
  return "normal";
}

Infraestrutura

  • Docker Compose com front, BFF e Nginx, iguais em desenvolvimento e produção.
  • Nginx como proxy reverso, publicado por DNS, com o SSE passando sem buffer.
  • Redis com o estado corrente (TTL de 60 s) e o lock do ciclo.
  • Server-Sent Events: um evento por ciclo para todos.
  • Prefect mantém as camadas de Waze, pluviômetros e NitBike no Portal ArcGIS.

  • Fluxos de coleta em Python no Prefect e documentação da arquitetura.

    Plataforma de automação com n8n

    Uso interno · sem acesso público

    Uma instância própria do n8n, montada por mim para o Escritório de Dados criar e rodar integrações entre sistemas sem depender de serviço externo. Nasceu na VM de homologação e hoje é ferramenta interna da equipe.

    Para que serve

    Recebe eventos de outros sistemas, confere os dados e grava o que é válido, sem cada integração precisar de um serviço novo. O primeiro fluxo tem webhook autenticado, validação, lógica condicional e gravação no PostgreSQL.

    Como eu fiz

    • Montei a stack com Docker Compose e o primeiro workflow da plataforma.
    • Testei payloads válidos e inválidos, inclusive JSON como objeto ou como lista.
    • Diagnóstico pelos logs e atualização de versão da instância.
    Etapa por etapa passe o mouse num card para ver o nó no fluxo acima

    O caminho de um evento, nó por nó

    1
    Entrada

    O sistema de origem chama o webhook

    origemPOST JSONWebhookBearer

    Outro sistema manda o evento num POST com JSON. O webhook só aceita a chamada com o token Bearer certo; sem ele, a resposta é 403 e nada segue.

    Habilidades desta etapaWebhooksn8n
    2
    Validação

    Um Code Node confere o corpo

    JSONCode Node4 camposdata ISO

    Em JavaScript, o Code Node confere event_id, source, timestamp e data, se o timestamp segue o padrão ISO 8601 e se data é um objeto. O evento pode chegar sozinho ou dentro de uma lista.

    Habilidades desta etapaJavaScriptn8n
    3
    Decisão

    O IF escolhe o caminho

    resultadoIFválidoinválido

    Com o resultado da validação, o IF manda o evento válido para o banco e o inválido para o caminho de erro, que responde com o motivo e não grava nada.

    Habilidades desta etapan8n
    4
    Gravação

    O evento válido vai para o PostgreSQL

    válidoPostgreSQLwebhook_events

    O evento aprovado é gravado na tabela webhook_events. Assim cada integração nova usa o mesmo caminho, sem precisar de um serviço próprio.

    Habilidades desta etapaPostgreSQL
    5
    Resposta

    Quem mandou fica sabendo

    gravadoRespostaHTTP 200origem

    No fim, o fluxo devolve 200 para o sistema de origem. Na demonstração acima, cada etapa marca o horário em que o ponto de luz chegou.
