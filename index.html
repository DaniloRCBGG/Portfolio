Gêmeo Digital de Niterói

Abrir o Gêmeo ↗

O alerta do Waze e a posição do ônibus já existiam, cada um no seu sistema. O Gêmeo cruza essas fontes no servidor a cada 30 segundos e entrega ao navegador um estado pronto: cada ônibus aparece no mapa 3D com a cor que diz se ele está numa área de alerta, num trecho congestionado ou nos dois.

O que eu fiz
  • Interface em React e TypeScript com ArcGIS Maps SDK: cena 3D, camadas, pop-ups próprios, símbolos, rótulos e filtros por período.
  • Integração com o BFF em Node.js/Express, que entrega o estado em tempo real por Server-Sent Events, com cache em Redis.
  • Execução com Docker Compose e publicação com Nginx como proxy reverso, incluindo os ajustes para o SSE funcionar através do proxy.
  • Fluxos de coleta de dados em Python com Prefect, e documentação técnica da arquitetura e da configuração.

Projeto full stack · Carol Rios Curly Studio · desde set/2026 · em testes com a cliente

Carol Rios Curly Studio

Ver versão de testes ↗

No salão, um horário só fica garantido depois que a cliente paga o sinal. O sistema leva essa regra para o site: a cliente escolhe o serviço, o tamanho do cabelo e o horário, que fica reservado por 30 minutos enquanto o Pix não é confirmado. Quando a equipe confirma o sinal, o atendimento entra na agenda, e ao concluir o estoque dá baixa sozinho nos produtos que aquele serviço consome naquele tamanho de cabelo.

3 perfiscliente, funcionária e gerente, com regras no banco
2×/semanabackup criptografado do banco, guardado por 90 dias
O que eu fiz
  • Site público em Next.js e TypeScript a partir do brandbook da marca, com tabela de valores por tamanho de cabelo e agendamento online.
  • Cadastro de clientes com email e senha ou conta Google, endereço preenchido pelo CEP via ViaCEP e exportação dos contatos para o WhatsApp.
  • Sinal por Pix com QR Code estático e copia e cola, confirmado pela equipe a partir do comprovante, com o Asaas pronto como modo automático opcional.
  • Banco no Supabase (PostgreSQL, Auth, Storage) com regras de acesso por perfil (RLS), reservas com expiração e baixa automática de estoque por gatilho.
  • Painel da equipe com agenda, clientes, serviços, estoque e fornecedores, e uma galeria interativa de antes e depois em revisão com a cliente.
  • Deploy automático da branch main no Netlify e backup com pg_dump criptografado via GitHub Actions. Desenvolvido com apoio do Claude Code.

Automação e integração · Prefeitura de Niterói · ferramenta interna em uso

Plataforma de automação com n8n

Uso interno · sem acesso público

Uma instância própria do n8n, montada por mim para que o Escritório de Dados crie e rode integrações entre sistemas sem depender de um serviço externo. Comecei na VM de homologação, preparando a infraestrutura em contêineres e um primeiro fluxo que recebe eventos de outro sistema, confere os dados e grava o que é válido no banco. Hoje o n8n é uma ferramenta interna usada pela equipe do escritório.

Contrato do evento no primeiro fluxo · simule um envio (exemplo fictício)
{
  "event_id": "evt-0001",
  "source": "sistema-exemplo",
  "timestamp": "2026-03-10T14:32:00-03:00",
  "data": { "tipo": "teste", "descricao": "payload de exemplo" }
}
HTTP 200campos conferidos, evento gravado em webhook_events
3 serviçosn8n, PostgreSQL e Redis no mesmo Docker Compose
5 etapasdo webhook à resposta HTTP no primeiro fluxo
4 camposevent_id, source, timestamp e data no contrato
1.x → 2.xatualização da versão do n8n feita na instância
O que eu fiz
  • Stack com Docker Compose reunindo n8n, PostgreSQL e Redis, com rede dedicada, volumes persistentes, healthchecks, reinício automático e rotação de logs.
  • Configuração por variáveis de ambiente, com credenciais e segredos fora dos arquivos do projeto.
  • Primeiro workflow da plataforma: webhook com autenticação Bearer, validação dos campos em um Code Node, lógica condicional e gravação dos eventos válidos no PostgreSQL.
  • Testes com payloads válidos e inválidos, incluindo os casos em que o JSON chega como objeto ou como lista.
  • Diagnóstico pelos logs, testes de Code Nodes em JavaScript e Python e atualização da instância da versão 1.108 para a 2.32.
